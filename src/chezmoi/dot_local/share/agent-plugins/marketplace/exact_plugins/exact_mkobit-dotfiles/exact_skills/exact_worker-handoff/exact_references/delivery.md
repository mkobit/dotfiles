# Assigned guest delivery

Use this procedure only when the assignment explicitly grants tracker, signing, remote-write, PR, and merge authority. The project supplies the tracker identity and native sync procedure, required remote, and dedicated signing subkey. The primary private key stays outside the guest. Stop if a prerequisite or authority is missing. Never substitute a normal signing key.

1. Sync and read the existing tracker with the supplied native procedure. For this Beads pilot, use `bd sync --no-adopt --remote <remote> --json` using the supplied named remote and the [tracker procedure](../../sbx-orchestrator/references/tracker.md) before reads and after writes. Select and claim one eligible issue, sync, and read back the claim. Resolve conflicts with native operations. Do not initialize a tracker or invent a remote.
2. Assess the unit, use one implementation subagent and a separate reviewer, and satisfy acceptance criteria. Run project checks and record commands, results, and skips. Repair only within the assigned scope.
3. Create signed commits with the assigned dedicated GPG subkey. Verify each commit signature and its signing identity before push. Push only the assigned branch to the required remote.
4. Find and reuse the existing PR for the branch and unit, or create one if none exists. Record its identity and head. Derive applicable expected CI results from `.github/workflows/ci.yml` and include separate repository required checks. For the current workflow and pilot scope, expect lint and type checks, skill-filter compatibility, both test matrix jobs, and all three integration matrix jobs. This is seven results; derive actual names and applicability from the workflow, not a separate list.
5. Wait for successful results for the final PR head. Missing, pending, failed, cancelled, skipped where required, or stale-head results block merge. An empty required-check result from `gh pr checks` does not prove workflow success. Repair CI only within scope, without disabling checks. After any new commit, verify signatures and wait for all applicable checks on the new final head.
6. If acceptance and repository rules permit, squash merge with matching-head protection against the verified final head. If the head changes, repeat the final-head checks; do not merge stale evidence. Confirm the merge before tracker closure.
7. Update and close the selected issue with delivery evidence using the supplied native procedure. Sync after writes and read back the closed state. Report issue, branch, PR, final head, signature verification, checks, merge, tracker state, logs, and blockers to the assigned return location, then exit. Do not select another unit.

On interruption, reconcile issue, native sync, branch, PR, CI, merge, and closure before retrying side effects. After a confirmed merge, resume only closure, sync, read-back, and report. Preserve logs and session; confirm the previous writer has stopped before resuming.
