# Native tracker coordination

Use the project's existing tracker identity, latest-state procedure, queue eligibility, and assigned operation authority. Require an explicit native remote only when the selected sync procedure needs one; the pilot's Beads replica requires it. A prompt or issue can define an assignment without a tracker. If any required queue or sync input is unavailable, preserve evidence and report the prerequisite; do not initialize, migrate, redirect, or invent a tracker or remote.

For the pilot's existing Beads replica, both host and guest use `bd sync --no-adopt --remote <remote> --json` before tracker reads and after writes. Use the supplied named remote, never an inferred default. Check installed `bd --help` and subcommand help for supported spellings. A sync is itself a remote operation: perform it only when assigned and authorized.

After a successful sync, inspect full candidate issues against the assignment's eligibility and authority; exclude human-only or unapproved work. Select one eligible issue and use the native atomic claim (`bd --actor <run-actor> update <issue> --claim --json`) only if authorized, with the assigned run identity. Sync after the claim, then read the issue back and verify its scope and owner before implementation. If a claim loses a race or the read-back differs, reconcile the native state and report or retry selection only within the assignment and a bounded effort; do not override another owner or invent a claim service.

Record progress and close the selected issue only when explicitly authorized and its exit criteria are met; when delivery includes a merge, verify the merge before closure. Sync after each write and read back closure after syncing. Refresh and verify scope and owner before authorized publication, merge, and closure. If closure fails after delivery, leave it pending and resume closure rather than repeating delivery. The host may independently contribute and sync tracker work without starting another guest or writing the guest's private checkout. Keep one active guest and one selected unit. For interruptions, reconcile existing issue and sync state before repeating external actions; retain branch, session, models, acceptance progress, and resume pointers through the project's mechanisms.

On sync conflict, failed publication, missing remote, or unavailable authority, preserve command outcomes and state, stop dependent work, and report the blocker. Retry routine transient failures within the native procedure; do not disable checks, auto-resolve conflicts, or introduce another sync service.
